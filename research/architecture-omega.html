Issue → Intent アダプタ

GitHubIssue → IntentSpace

packages/coding-agents/omega-system/adapters/issue-to-intent.ts (306行)

入力

  • GitHubIssue — title / body / labels / assignees
→

出力

  • IntentSpace — goals / preferences / objectives / modality

主要ロジック

  1. ラベル → 優先度マッピング — priority:P0=critical, P1=high, P2=medium, P3=low
  2. ラベル → タイプ推論 — type:bug=fix, type:feature=feature, type:refactor=refactor
  3. チェックボックス解析 — - [ ] ... / - [x] ... を goals として抽出（完了/未完了を区別）
  4. 番号付きリスト解析 — 1. ... 2. ... 形式を順序付きgoalとして抽出
  5. 本文セクション抽出 — 「## 目的」「## 受入基準」等の見出しから objectives/successCriteria を構造化
  6. modality推定 — assignee有無・ラベルから interactive / autonomous / hybrid を決定

特徴

  • Issue本文の自然言語を決定論的に IntentSpace に正規化
  • 抽出失敗時は title をフォールバック goal として採用
  • preferences はラベルquality:* / speed:*から自動生成

  • artifact追跡：各タスクの生成物を型付きで追跡

θ₃

Allocation — エージェント割当

allocation.ts

変換: θ₃ : 𝕋 × W → A

入力

  • TaskSet — θ₂の出力タスク集合 (DAG付)
  • WorldSpace — プロジェクト世界モデル

出力

  • AgentAllocation — Worker割当 + 実行バッチ + メトリクス

主要ロジック

  1. findBestAgent(task, capabilities) — 6種のエージェント候補をスコアリング。要求スキル一致度・専門領域マッチ・品質スコア・コスト(token推定)を加重評価し、最適エージェントを選定。
  2. createWorkerAssignments(tasks, agents) — 最大並列度と「1 worker あたり最大3タスク」制約のもとでタスクをWorkerに束ね、負荷分散する。
  3. createExecutionBatches(dag, assignments) — DAGのレベル(トポロジカル深さ)ごとにバッチを構成。同レベル内タスクは並列実行可能としてグルーピング。
  4. computeMetrics() — 利用率(utilization)・コスト見積・最適化スコアを算出しAgentAllocation.metricsに格納。

特徴

  • コスト意識: 入出力tokenを推定し総コストを最小化
  • 品質スコア加算: 過去実績に基づく信頼度をスコアに反映
  • DAG準拠並列化: 依存関係を保持したままレベル並列実行
  • 6種エージェント候補 (Coordinator/CodeGen/Review/Issue/PR/Test) から動的選択

主要型

  • AgentCapability — エージェントのスキル・専門領域・品質スコア・コスト係数
  • WorkerAssignment — Worker単位のタスク束 (agentId + tasks[] + 推定時間)
  • ExecutionBatch — DAGレベル単位の並列実行バッチ (level + workers[])
θ₄

Execution — 実行

execution.ts

変換: θ₄ : A → R

入力

  • AgentAllocation — θ₃の割当結果

出力

  • ResultSet — タスク結果集合 + パフォーマンス統計

主要ロジック

  1. executeTask(task) — タスク単体の実行シミュレーション。成功率95%、レイテンシ50–500msを模擬し、TaskResultを生成。
  2. executeWorker(worker) — Worker内タスクを並列または順次に実行。失敗時はretryFailedTasksで再試行。
  3. executeBatch(batch) — バッチ内Workerを並列起動しつつ、依存順序を尊重して進行。BatchResultに集約。
  4. aggregatePerformance() — 全バッチ完了後に成功率・平均実行時間・スループット(tasks/sec)・並列度を集計。

特徴

  • 非同期バッチ処理 (Promise.all ベース)
  • retryFailedTasks による回復性
  • アーティファクト記録 (生成物・ログ・メトリクス)
  • Issueまで遡れるトレーサビリティ保持

主要型

  • TaskResult — 個別タスクの成否・所要時間・アーティファクト
  • WorkerResult — Worker単位の集約結果
  • BatchResult — バッチ単位の並列実行結果
  • ResultSet — 全体結果 + パフォーマンスサマリ

プロジェクトコンテキストをWorldSpace(世界モデル)に変換するアダプタ層。

  • inferArchitecturePatterns() — ディレクトリ構造と依存関係から アーキテクチャパターン (Layered / Hexagonal / MVC / Event-driven 等) を推論。

  4. infrastructure — 永続化・外部I/O実装
  5. interface — CLI/API/UI境界
  6. shared — 横断的ユーティリティ・型

Integration — 統合・パッケージング

integration.ts

θ₅ : R → D

入力: ResultSet　出力: Deliverable

主要ロジック

  • categorizeArtifacts() — 成果物を5分類（code / test / doc / config / report）に振り分け
  • calculateCodeChanges() — 言語判定 + diff 計算で変更行数を集計

  • スコア配分: 実行 40% / カバレッジ 30% / エラー 30%
  • PR 自動パッケージング（artifacts → commit → PR draft）

ステータス

ready needs-review blocked

learning.ts

  • フィードバックループで次回実行品質を継続的に改善
Ω

Ω-Engine — 完全パイプライン

omega-engine.ts（545 行）

Ω : I × W → R / E = θ₆ ∘ θ₅ ∘ θ₄ ∘ θ₃ ∘ θ₂ ∘ θ₁

パイプライン構成

θ₁ Perception → θ₂ Intent → θ₃ Plan → θ₄ Execution → θ₅ Integration → θ₆ Learning

OmegaEngineConfig

  • validateBetweenStages — ステージ間で型・契約を検証
  • stopOnValidationError — 検証失敗時に即停止
  • enableLearning — θ₆ 学習ステージを有効化
  • maxExecutionTimeMs = 600000（10 分上限）
  • maxRetries = 3

実行制御

  • リトライ: 指数バックオフ 2^attempt × 100ms
  • θ₆ のみ非致命的（失敗しても全体は継続）
  • trace.intermediates に全ステージの中間結果を保存
  • コールバック: onStageComplete / onStageError

エクスポート

  • OmegaEngine クラス
  • omega() — 標準実行
  • omegaWithoutLearning() — θ₆ をスキップ
  • omegaStrict() — 厳格モード（検証失敗で即停止）

Adapter — deliverable-to-report.ts

  • ステータスマッピング: ready → success / needs-review → partial / blocked → failure
  • スコア → レターグレード変換: 90+ A / 80+ B / 70+ C / 60+ D
  • Deliverable を既存 Agent レポート形式へブリッジ

Adapter — omega-agent-adapter.ts

  • OmegaAgentAdapter クラス: execute() / executeParallel() / executeSequential()
  • Agent 能力マッピング例: CoordinatorAgent → task-decomposition 等
  • オプション: skipPlanning / forceSequential / enableLearning
  • 既存 21 Agent を Ω-Engine 上で実行可能にする統合層
