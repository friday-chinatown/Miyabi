@miyabi/agent-sdk

v0.1.0 7 agents 6 clients 3-tier fallback ESM strict

Miyabi の エージェント実行基盤。GitHub Issue を入力に、分析→コード生成→レビュー→PR 作成まで一気通貫で自動化する 7 つの専門 Agent と、それらを支える 6 つの Client、そしてタスクカテゴリに応じて最適な LLM プロバイダー（Claude CLI / Codex CLI / Anthropic API）を選択する TaskRouter を提供する。Claude CLI と Codex CLI を優先することで、サブスクリプション内で $0 実行 を実現し、API キーが無い環境では Anthropic API に自動フォールバックする。packages/cli や packages/coding-agents から import される、Miyabi の中核 SDK。

src/agents/ — 7 つの専門エージェント

  • CoordinatorAgent.ts 288 行 — 最上位意思決定 Agent。Issue を解析しタスクを分解、TaskDAG（nodes / edges）を生成、Critical Path 特定、並列実行可能グループの抽出、推定実行時間の算出を担う。maxConcurrency = 3 で並列度制御。
    export: CoordinatorAgent, CoordinatorInput, CoordinatorOutput / deps: なし（純ロジック）
  • IssueAgent.ts 278 行 — GitHub Issue を取得し 53 ラベル分類体系に従って自動分類。type / complexity / priority / labels を判定。3 モード実行: ① ClaudeCodeClient（claude -p, $0） ② AnthropicClient（API 直接, 有料） ③ Mock（キーワードベース, フォールバック）。
    export: IssueAgent, IssueInput, IssueOutput / deps: AnthropicClient, ClaudeCodeClient, GitHubClient
  • CodeGenAgent.ts 342 行 — ★ Miyabi の心臓部。要件からコード本体とテストを生成し、qualityScore を返す。4 層フォールバック: ① Codex CLI（コーディング特化、$0） ② Claude Code CLI（claude -p, $0） ③ Anthropic API（有料） ④ Mock テンプレート。コンストラクタで useCodex / useClaudeCode / anthropicApiKey を切り替え。生成物は {path, content, action: create|modify|delete} 形式。
    export: CodeGenAgent, CodeGenInput, CodeGenOutput / deps: AnthropicClient, ClaudeCodeClient, CodexClient, GitHubClient
  • ReviewAgent.ts 362 行 — ★ コード品質判定 Agent。生成コードを 0–100 でスコアリングし、severity 付き issues, coverage, suggestions を返す。minQualityScore（既定 80） を満たせば passed=true、満たさなければ Auto-Loop で CodeGen をリトライ（最大 3 回）。CodeGenAgent と同じ 4 層フォールバックを持つ。
    export: ReviewAgent, ReviewInput, ReviewOutput / deps: AnthropicClient, ClaudeCodeClient, CodexClient
  • PRAgent.ts 262 行 — Branch 作成 → ファイル commit → Draft PR 作成。Conventional Commits 準拠のメッセージを自動生成し、qualityReport を PR 本文に埋め込む。Issue 番号からブランチ名と PR タイトルを導出。
    export: PRAgent, PRInput, PROutput / deps: GitHubClient
  • TestAgent.ts 184 行 — テストコマンド実行・カバレッジ計測・失敗レポート生成を担当。coverageThreshold = 80, timeoutThreshold = 300_000ms。totalTests / passedTests / failedTests / failures[] を返す。
    export: TestAgent, TestInput, TestOutput / deps: なし（child_process）
  • DeploymentAgent.ts 107 行 — CI/CD 自動化。pre-deploy チェック（tests / lint / typeCheck / securityAudit）→ 環境別デプロイ（staging / production）→ ヘルスチェック → 失敗時ロールバック。dryRun モードあり。
    export: DeploymentAgent, DeploymentInput, DeploymentOutput / deps: なし
  • index.ts 24 行 — 7 Agent の barrel export

@miyabi/coding-agents

Ω-System 6段階θ変換 (omega-system/transformations/)

  1. θ₁ understanding.ts — Issue/Intent から戦略計画 StrategicPlan を導出 (理解段階)
  2. θ₂ generation.ts — StrategicPlan → TaskSet 生成 (タスク生成段階)
  3. θ₃ allocation.ts — TaskSet → AgentAllocation 割当 (Agent最適配分)
  4. θ₄ execution.ts — AgentAllocation → ResultSet 並列実行
  5. θ₅ integration.ts — ResultSet → Deliverable 統合
  6. θ₆ learning.ts — Deliverable → Knowledge 学習・フィードバック

合成式: E = θ₆ ∘ θ₅ ∘ θ₄ ∘ θ₃ ∘ θ₂ ∘ θ₁ 数学定義: Ω: I × W → R (Intent空間 × World空間 → Result空間)。omega-engine.ts が ExecutionTrace / PipelineState / PipelineStage として全段階を計測しトレース化。各段階に validatePlan/validateTaskSet/validateAllocation/validateResultSet/validateDeliverable/validateKnowledge の検証関数を持つ。

Water Spider パターン (water-spider/)

トヨタ生産方式の「資材補充係 (水蜘蛛)」に由来。WaterSpiderAgent は BaseAgent を継承し、 SessionManager で各 Worktree セッションの SessionStatus (running / idle / stopped / error) を monitorInterval (既定 5000ms) で監視、maxIdleTime (既定 30000ms) を超えたセッションへ WebhookClient 経由で「continue」信号を JIT 送出する。autoRestart 有効時は停止セッションを自動再起動。 Claude Code セッションが「止まらないライン」となるよう保証する自律継続コントローラ。

CoordinatorAgent (coordinator/coordinator-agent.ts)

Miyabi階層の最重要Agent。責務は (1) Issue → Task分解、(2) DAG構築、(3) トポロジカルソート、 (4) Agent割当、(5) 並列実行制御、(6) 進捗監視。IssueAnalyzer, DAGManager, PlansGenerator, WorktreeManager, GitHubClient, IssueTraceLogger を統合し、 オプションで OmegaAgentAdapter 経由で Ω-System に処理を委譲して 6段階θ変換実行へ昇格できる。 WorktreeExecutionContext により worktree 単位の並列タスクをハンドリング。
