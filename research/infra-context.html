6. イベント駆動アーキテクチャ

目的

  • Issue作成→Deploy完了まで手動トリガーゼロの完全自動パイプライン

原因

  • 手動トリガーによる遅延と工程漏れ

対処

  • webhook-handler.yml — 中央ルーター: 全イベント分類→適切なWorkflow起動
  • state-machine.yml — ラベル駆動状態遷移
    • initial-triage: opened → pending + 優先度(P0/P1/P2)
    • coordinator-assignment: agent:coordinator → analyzing
    • pr-created: PR opened → reviewing
    • pr-merged: merged → done
  • autonomous-agent.yml — Agent実行エンジン
    • check-trigger: 🤖agent-execute / /agent コマンド / workflow_dispatch
    • execute-agents: npm run agents:parallel:exec --concurrency 3
  • webhook-fallback.js (Issue #137) — オフラインキュー
    • 5秒タイムアウト (AbortController) → ~/.ai/logs/webhook-queue/ にJSON保存
    • node webhook-fallback.js flush で一括再送（最大3リトライ → failed/ 移動）
    • git操作は決してブロックしない (graceful degradation)

8. CLIタイムアウト問題

目的

  • 長時間タスクで CLI 呼び出し (child_process.spawn) がタイムアウトする問題の解決

原因

  • 固定タイムアウト設定 (Codex 120秒, Claude healthCheck 5秒等)
  • 無出力状態を「死亡」と誤判定
  • 大規模コード生成で5分以上要する場合がある

対処（5段階、軽い順）

  1. idle timeout + 延長: stdout チャンク毎にタイマーリセット、全体30分まで延長
  2. ストリーミング受信: --output-format stream-json で行ごとparse
  3. タスク分割: CoordinatorAgent DAG で15分制約内に強制分解
  4. バックグラウンドジョブ: JobRunner.ts新設、detached spawn + .miyabi/jobs/id.json
  5. GitHub Actions委譲: Issue作成 → Actions上でagent実行 → PR/コメントで結果返却
