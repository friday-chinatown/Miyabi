🏭 ワークフロー：Issueから本番デプロイまで

Miyabiの一番すごいところ：GitHub Issue（お仕事の依頼書）を書くだけで、AIが自動的にコードを書いて、テストして、本番環境に届けてくれます。 全部で9つのステップがあり、通常10〜15分で完了します。

💡
超初心者向け解説： 「Issue」とは、GitHubにある「お仕事の依頼メモ」のこと。「この機能を追加して」「このバグを直して」と書くだけで、AIが自動で実行してくれます。人間のプログラマーに頼むのと同じ感覚です。

🐳 Docker & デプロイ

Dockerは「アプリの箱詰め技術」です。Miyabiはマルチステージビルドという技術で、 軽くて安全なコンテナを作成します。まるでロシアの入れ子人形（マトリョーシカ）のように、必要なものだけを最終形に残します。

💡
Dockerとは？ アプリを動かすために必要なもの（コード、ライブラリ、設定）を全部まとめて「箱（コンテナ）」に入れる技術です。 この箱さえあれば、どのサーバーでも同じように動きます。「引っ越し用の段ボール」のようなものです。

マルチステージビルド（4段階）

📥
Stage 1: base

土台づくり。Alpine Linux（軽量OS）にgitやSSHなど基本ツールをインストール。

node:20-alpine
📦
Stage 2: deps

本番に必要なライブラリだけをインストール。開発用ツールは含めない。

pnpm 9 / production deps only
🔨
Stage 3: builder

全ライブラリをインストールしてTypeScriptをコンパイル（翻訳）。ビルド完了後は不要に。

全deps + TypeScriptビルド
🚀
Stage 4: runtime（最終形）

実行に必要な成果物だけを集めた最終コンテナ。非rootユーザーで安全に実行。

非rootユーザー(miyabi:1001) / 最小構成
🎯
なぜ4段階もあるの？ 料理に例えると：材料を買う(base) → 必要な調味料を並べる(deps) → 料理する(builder) → 盛り付けて提供する(runtime)。 最終的にお客様に出すのは「盛り付けた料理」だけ。鍋やまな板は不要なので含めません。これによりコンテナが軽くて安全になります。

セキュリティと運用の特長

🔒
非rootユーザー実行
miyabiユーザー(UID:1001)で実行。管理者権限を使わない安全設計。
⛰
Alpine Linux基盤
5MB程度の超軽量OS。攻撃対象面が極めて小さい。
📋
本番deps限定
開発用ツールを含めず、脆弱性リスクを最小化。
🖥
マルチプラットフォーム
amd64/arm64両対応。IntelでもM1/M2 Macでも動作。
💓
ヘルスチェック
30秒間隔で生存確認。問題があれば自動で検出。
📊
リソース制限
CPU: 最大2.0 / RAM: 最大2GB。暴走を防止。
