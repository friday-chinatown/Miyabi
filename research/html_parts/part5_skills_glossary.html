23 のスキル

Miyabi が持つ 23 のスキルは 5 つのカテゴリに分類されます。各スキルは特定のキーワード（トリガー）で自動的に起動します。

Agent Skills -- 7 スキル
🎯 Coordinator
しきるん -- 全体を指揮する司令塔
Issue を分析して小さなタスクに分解し、どのエージェントが何をするかを決めて、全体の進行を管理します。
decompose this issue run full pipeline coordinate agents
🔍 Issue Agent
みつけるん -- Issue を分析する探偵
GitHub Issue を読み取り、53 種類のラベルから適切なものを自動で付け、複雑さを評価します。
analyze this issue label issues triage new issues
📝 Code Reviewer
100 点満点でコードを採点する審査員
コードを正確さ（30%）、セキュリティ（25%）、性能（20%）、保守性（15%）、テスト（10%）で 100 点満点で採点します。80 点以上で合格。
review this code check this PR find bugs
🔗 PR Agent
Pull Request を作成する連絡係
ブランチの命名規則に従い PR を自動作成します。マージには Guardian の承認が必要です。
create PR merge this PR
🚀 Deploy Agent
はこぶん -- 本番環境に届ける配達員
テスト、型チェック、lint、レビュー、セキュリティを全て確認してからデプロイ。失敗時は自動ロールバック。
deploy to production rollback deployment
🧪 Test Generator
テストコードを自動で書く職人
Vitest、Playwright、Testing Library を使い、AAA パターン（準備・実行・検証）でテストを生成。カバレッジ 80% 以上が目標。
write tests improve coverage test first
🤖 Autonomous Coding
自律的にコードを書く AI プログラマー
Claude Code CLI を使って、プロンプトからコードを自律的に生成・実行します。入力のサニタイズも行います。
autonomous coding coding agent
Platform Skills -- 3 スキル
⚙️ Pipeline
複数の処理をつなげるベルトコンベア
パイプ（|）、AND（&&）、OR（||）、並列（&）の演算子でコマンドを組み合わせます。失敗したステップから再開可能。
run pipeline full cycle preset pipeline
✅ Quality Gate
品質の門番 -- 基準に満たないコードは通さない
100 点満点で 6 つの観点から評価。90 点以上で「優秀」、80 点以上で「良好」、60 点未満は自動リトライ（最大 3 回）。
quality check quality gate
🏛️ GitHub OS
GitHub をオペレーティングシステムとして使う
Issues をタスクキュー、Labels をステートマシン、Projects V2 をデータ層、Actions を実行エンジンとして活用する中核アーキテクチャ。
github os issue-driven

タスクは 10 の状態を持ち、決められたルールに従って状態が変わります。これを「ステートマシン（状態機械）」と呼びます。

各状態のかんたん説明

📝 draft

タスクが作られたばかり。まだ誰にも割り当てられていない状態です。

⏳ pending

実行の順番を待っている状態。キューに入っています。

🔍 analyzing

Issue Agent が Issue を分析中。ラベル付けと複雑度評価をしています。

🔨 implementing

CodeGen Agent がコードを書いている最中です。

📋 reviewing

Review Agent がコードを 100 点満点で採点中。80 点未満なら差し戻し。

🚀 deploying

本番環境にコードを配置中。テスト → ビルド → デプロイ → ヘルスチェック。

✅ done

全工程が完了。Issue がクローズされ、PR がマージされます。

🛑 blocked

他のタスクや外部要因で先に進めない状態です。

❌ failed

処理が失敗しました。pending に戻ってリトライできます。

🚫 cancelled

タスクが取り消されました。draft に戻して復活も可能。

タスクの 7 つのタイプ

feature -- 新機能 bug -- バグ修正 refactor -- リファクタリング docs -- ドキュメント test -- テスト deployment -- デプロイ chore -- 雑務

データモデル

Miyabi のシステムで使われる主要なデータの型（かた）を紹介します。それぞれがどうつながっているかを見てみましょう。

📋 ManagedTask

interface -- タスクの全情報
  • currentState -- 今の状態（10 種類）
  • type -- タスクの種類（7 種類）
  • priority -- 優先度
  • assignedAgent -- 担当エージェント
  • retryCount -- リトライ回数
  • stateHistory -- 状態変更の履歴
  • githubIssueNumber -- 紐付く Issue 番号
→ BaseTask を拡張

🤖 AgentType

type -- エージェントの種類
  • coordinator -- 司令塔
  • codegen -- コード生成
  • review -- レビュー
  • issue -- Issue 分析
  • pr -- PR 管理
  • deployment -- デプロイ
  • test -- テスト
→ ManagedTask が参照

📨 AgentMessage

interface -- エージェント間の手紙
  • from -- 送信元エージェント
  • to -- 送信先エージェント
  • type -- メッセージの種類（8 種）
  • priority -- 優先度（0-3）
  • payload -- メッセージ本文
  • ttl -- 有効期限（ミリ秒）
→ AgentType を使用

📊 ExecutionResult

interface -- 実行結果の記録
  • taskId -- タスク ID
  • success -- 成功したか
  • state -- 実行後の状態
  • durationMs -- 所要時間
  • agentType -- 実行したエージェント
  • artifacts -- 成果物のリスト
→ ManagedTask から生成

🕸️ DAGResult

interface -- タスク依存関係の地図
  • nodes -- タスクの一覧
  • edges -- タスク間のつながり
  • levels -- 並列実行できるグループ
  • criticalPath -- 最長経路
  • estimatedDurationMinutes -- 推定時間
→ ManagedTask[] を含む

🔄 Workflow

interface -- ワークフロー定義
  • id -- ワークフロー ID
  • name -- 名前
  • nodes -- ノード（エージェント等）
  • edges -- ノード間の接続
  • createdAt -- 作成日時
→ AgentNodeData 等を含む

データモデル間のつながり

ManagedTask --extends--> BaseTask
ManagedTask --uses--> AgentType
ManagedTask --uses--> TaskState
ManagedTask --contains--> TaskStateTransition[]
DAGResult --contains--> ManagedTask[]
ExecutionResult --references--> ManagedTask
AgentMessage --uses--> AgentType
AgentMessage --uses--> MessageType
Workflow --contains--> AgentNodeData
AgentRegistry --manages--> IAgent[]

設計パターン

Miyabi で使われている設計パターンを、日常の例えで分かりやすく紹介します。パターンとは「よくある問題の解決策のテンプレート」です。

👑
Singleton
一つだけ存在するもの
🏰 国に王様は一人だけ
システム全体で 1 つしか存在してはいけないオブジェクトに使います。例えば、ファイル書き込みの窓口が 2 つあると混乱するので、1 つに統一します。
使用先: AsyncFileWriter, GitHubClient, AgentRegistry
🏭
Factory
工場
🚗 車の種類を言うだけで工場が作ってくれる
「コードレビューのエージェントが欲しい」と種類を指定するだけで、正しいエージェントを自動で作ってくれる仕組みです。
使用先: AgentFactory, register*Command
🧱
Builder
段階的な組み立て
🍔 ハンバーガーを一段ずつ組み立てる
複雑なオブジェクトを一度に作るのではなく、パンを置き、パティを乗せ、チーズを加え...と段階的に構築します。
使用先: AgentConfig, PipelineContext
🚦
State Machine
状態機械
🚦 信号機は赤 → 青 → 黄 の順でしか変わらない
タスクの状態が決められたルール通りにしか変わらないようにします。「下書き」からいきなり「完了」にはできません。
使用先: TaskStateMachine（10 状態 28 遷移）
🔔
Observer
監視者
📱 YouTube のチャンネル登録 -- 新着動画が来たら通知
「何か変わったら教えて」と登録しておくと、変更があったときに自動で通知が届く仕組みです。ダッシュボードのリアルタイム更新に使います。
使用先: EventEmitter, WebSocket Dashboard
🎯
Strategy
戦略の差し替え
📷 カメラのレンズ交換 -- 状況に合わせてレンズを変える
同じ目的（リトライ、コンフリクト解決など）でも、場面に応じてやり方（戦略）を簡単に切り替えられます。
使用先: RetryStrategy, ConflictResolution
🏠
Facade
窓口（受付）
🏨 ホテルのフロントデスク -- 裏の複雑さを隠す
複雑な内部処理をシンプルな窓口で隠します。「分析して」と一言言うだけで、裏で HTTP 通信やセッション管理が動きます。
使用先: ContextEngineering クラス
⛓️
Chain of Responsibility
責任の連鎖
🏢 会社の承認フロー -- 課長 → 部長 → 社長
品質チェックを段階的に行います。コード生成 → レビュー → 合格？ → PR 作成。不合格なら前に戻ってやり直し。
使用先: Quality Gate チェーン
🌲
Composite
入れ子構造
📁 フォルダの中にフォルダ -- 同じ操作でどちらも扱える
単純なコマンドも、複数のコマンドを組み合わせた複雑なパイプラインも、同じ方法で実行できます。
使用先: Pipeline コマンド合成（|, &&, ||, &）
📜
Template Method
テンプレートメソッド
🍳 レシピの手順 -- 基本は同じ、具材だけ変える
全エージェント共通の「開始 → 実行 → 記録 → 終了」という流れは固定し、「実行」の中身だけ各エージェントが自由に決めます。
使用先: BaseAgent.run() -- 7 + 14 エージェント共通
🔌
Adapter
変換器
🔌 海外旅行の電源変換プラグ
CLI コマンドとして作られた機能を、MCP プロトコル（別の形式）でも使えるように変換します。
使用先: MCP Server が CLI コマンドをラップ
📩
Command
命令オブジェクト
📩 注文書 -- 「何をするか」を紙に書いて渡す
操作の内容をオブジェクトとして保存するので、キューに入れたり、ログを取ったり、失敗時に途中から再開できます。
使用先: CLI 30 コマンド, Pipeline 演算子
